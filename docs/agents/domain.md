# Domain docs

## Read before exploring

- Read root `GLOSSARY.md` for domain terms.
- Read decisions in `docs/adr/` relevant to the work.
- If either is absent, proceed silently. Create domain documents when a term or decision is actually resolved through `/domain-modeling`.

## Layout

This project has one domain context: `GLOSSARY.md` at the root and architecture decisions in `docs/adr/NNNN-<decision>.md`.

## Use the project vocabulary

Use glossary terms in issues, designs, tests, and code. If a necessary concept is missing, identify the gap for `/domain-modeling`.

## Surface decision conflicts

If a proposal conflicts with an existing ADR, identify the ADR and explain why the decision should be reconsidered before changing the behavior.
